# TaskLattice Veritas v0.1.0

First packaged release of the desktop guardrail testing workbench, API and CLI.

- Test F5 Scan and LiteLLM generic guardrail services through the shared promptfoo SDK engine.
- Browse 17 catalog sources with pinned provenance, prepare selected scopes, and run repeatable seeded samples with concurrency and repeated checks.
- Inspect saved Reports, request/response evidence, intervention metrics, conservative annotated PII redaction outcomes, execution status and latency.
- Re-score saved evidence without new Target traffic and compare compatible Reports against a chosen baseline.
- Use the refined desktop workspace, status filters, Dataset browsing and per-Dataset metrics in light or dark mode.
- Deploy one persistent instance with Compose or Helm. Native Linux amd64 and arm64 images are tested before publication.

## Install

```sh
mkdir veritas && cd veritas
curl -fsSLO https://github.com/tasklattice/tasklattice-veritas/releases/download/v0.1.0/compose.yaml
docker compose pull
docker compose up --no-build -d
```

Open <http://localhost:38100>. Optionally run `docker compose exec veritas npm run veritas -- demo` to exercise both protocols against a temporary local mock.

```sh
helm upgrade --install veritas oci://ghcr.io/tasklattice/charts/tasklattice-veritas \
  --version 0.1.0 --namespace veritas --create-namespace --wait --timeout 5m
kubectl -n veritas port-forward service/veritas-tasklattice-veritas 38100:80
```

The image is `ghcr.io/tasklattice/tasklattice-veritas:0.1.0`. The attached
`release-manifest.json` records the source revision and image digest.
`SHA256SUMS` covers the Helm archive, Compose file and release manifest.

## Measurement and deployment scope

Synthetic CI checks validate the tool's behavior; they do not establish the
accuracy or cost of a deployed Guard. Report metrics describe Endpoint actions,
and annotated redaction checks cover the supplied spans. Confirm real Guard
policy/model routing before interpreting a benchmark. Raw datasets, credentials,
Targets, private Reports and workstation captures are excluded from the release.

Veritas runs one process with persistent filesystem state and assumes a trusted
operator. Keep the default loopback/port-forward access, or configure an
authenticated proxy before remote access. Stop active tests and back up the
entire state volume before upgrading. Upstream dataset licenses and gated access
requirements continue to apply.
